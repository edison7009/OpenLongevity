# AI4L 本地化审计方法

状态：`working-standard`  
本地版本：`0.1`  
上游基线：AI4L `1.2.0` / `bfe6083a1ca04223a245b9a5a0a8be41f021998f`  
日期：`2026-07-20`

## 为什么引入

Open Longevity 已有来源政策、Tier 规则和普通读者档案格式，并通过这套方法补充可重复的**第二遍检查**。AI4L 最有价值的部分不是某篇现成综述，而是把证据综述拆成创建、独立审计、修正和再审计，并要求逐条核验链接与结论。

本方法把 AI4L 的 404 项规范压缩为 47 个适合 Open Longevity 的核心检查项。压缩不是降低标准，而是去掉不适用的排版、商业数据库、品牌和人群假设，把检查集中到“结论能否追溯、边界是否说清”。

## 双层文档

每份 dossier 分为两个阅读层：

1. **读者层**：30 秒结论、普通语言机制、人体证据、食物、补剂和安全边界；
2. **研究层**：人群与结局、效应量、风险、影响因素、相互作用、监测、利益冲突、在研试验和审计记录。

研究层可以更全面，但不能把读者层重新变成一篇难以阅读的长报告。

## 审计循环

```text
定义问题 → 检索与归档 → 写 dossier → 独立审计
                                  ↓
                         修正可修正问题
                                  ↓
                         重新审计并留痕
```

### 角色分离

- 作者不能把自己的写作过程当成审计证据；
- 审计从 dossier、论文记录和原始快照重新开始；
- 审计发现缺证据时标记缺口，不能靠常识补写；
- 同一轮可修正格式、遗漏和引用错误，但新医学结论必须重新经过来源流程。

### 审计状态

| 状态 | 含义 |
|---|---|
| `pending` | 尚未审计 |
| `partial` | 已审计，但有影响完整性的失败项或待核来源 |
| `passed` | 核心项通过，未发现阻断当前结论的问题 |
| `stale` | 证据截止日过旧，或出现可能改变结论的新资料 |

`passed` 只表示通过本地检查表，不等于医学结论绝对正确。

## 十个质量门

完整 47 项模板见 [intervention-audit.md](../templates/intervention-audit.md)。

| 质量门 | 核心问题 |
|---|---|
| A. 范围与元数据 | 人群、干预、剂量、周期、结局和证据截止日是否明确？ |
| B. 检索与来源身份 | 是否记录检索；链接、题目、PMID/DOI/NCT 是否互相匹配？ |
| C. 获益 | 是否优先人体功能/临床结局；是否给效应量和不确定性；阴性结果是否显眼？ |
| D. 风险 | 是否覆盖常见和严重风险、长期未知、特殊人群与停止条件？ |
| E. 适用范围 | 年龄、性别、基线状态、疾病和药物是否会改变结论？ |
| F. 实际使用 | 研究剂型、标签、暴露、质量、成本和机会成本是否区分？ |
| G. 监测与未来证据 | 是否说明成功/失败、监测、在研试验和会改变结论的新证据？ |
| H. 利益与偏倚 | 资金、作者利益、商业来源和选择性报告是否记录？ |
| I. 可读性与结论 | 是否先讲人话；结论是否只总结正文且保留不确定性？ |
| J. 完整性与留痕 | Tier、目录、正文、论文库、链接和审计记录是否一致？ |

## 与 AI4L 不同的地方

### 1. 普通读者优先

AI4L 的目标读者偏向愿意执行复杂方案的健康优化人群。Open Longevity 仍以普通读者为入口，专业信息放在研究附录，不要求全文使用临床术语。

### 2. 不默认提供“治疗方案”

研究中的剂量用于描述证据，不自动变成个人服用方案。没有指南或明确临床边界时，只说明研究如何做、证据缺什么，不拼接所谓“标准长寿协议”。

### 3. 不采用无依据的最优区间

监测优先采用临床指南、监管机构或经过验证的参考范围。所谓“功能医学最优范围”只有在来源和证据单独审查后才可作为争议观点出现。

### 4. 不做品牌推荐

可以解释标签、剂型、纯度和第三方检测，但默认不列品牌。ConsumerLab、Examine、Grokipedia、专家视频等只能作为线索或背景，不能替代主要证据。

### 5. 不追求虚假的满分

链接无法访问、全文缺失、资金来源不明或长期数据不存在时，保留 `partial` 或 `fail`。未知本身就是结果，不能为了获得 100% 通过率而改写成肯定结论。

## Tier 与审计的关系

- Tier 表示当前证据与适用条件；
- 审计状态表示档案是否完成质量检查；
- 审计失败不自动降 Tier，但可能暴露足以改变 Tier 的证据遗漏；
- Tier 改变必须写明是哪条新证据或哪项错误导致；
- 人物使用、产品销售和机制热度仍不能提高 Tier。

## 上游局限

AI4L 明确指出：干净的审计仍可能漏错，100% 只代表通过检查表，工具可用性和模型质量会影响结果，证据综述不能替代医疗照护。Open Longevity 保留这些限制，并进一步要求本地快照和人工可追溯记录。
